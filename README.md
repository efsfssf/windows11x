# Windows 11X — исследовательский атлас

Сайт проекта WCOS / NT 26100 с общим планом и редактором содержимого.

- **Без входа:** просмотр всех страниц, исследований, отметок и заметок; поиск, чтение и скачивание документов, экспорт.
- **После входа владельца:** общие отметки и заметки, добавление задач, импорт плана, редактор сайта и восстановление полной копии.
- **Редактор:** название и навигация, дата среза и SHA, тексты страниц, карточки обзора, лестница доказательств, исправления, этапы и задачи, события с любыми датами, архитектура, роли томов и фазы, словарь, метаданные и содержимое исследований. Записи можно добавлять, удалять и переставлять.

## Комментарии к задачам

Вместо одной заметки у задачи — список комментариев. Откройте задачу, укажите **дату исследования**, введите результат и нажмите **Добавить комментарий**. Можно добавить несколько записей, изменить текст или дату и удалить отдельный комментарий. Время добавления показывается отдельно от даты исследования. Без входа доступны только чтение и экспорт.

Прежние заметки автоматически становятся комментариями с пометкой **Дата исследования не указана**: дата не придумывается. Владелец может указать её при редактировании. Перенос сохраняется на сервере вместе со следующим изменением плана. Старые экспорты по-прежнему импортируются, а новые копии и сводка для ИИ включают комментарии и их даты.

Изменения сохраняются **на сервере** и видны другим посетителям после обновления страницы. База данных и сборка JavaScript не нужны. Открытие `index.html` без PHP даёт только просмотр исходного среза; для актуальных общих данных открывайте адрес сайта.

## Первое включение на хостинге

Нужен PHP **8.1+** с обычными расширениями `json` и `session`, HTTPS и доступ PHP на запись в закрытую папку **вне корня сайта**. Открытой регистрации и пароля по умолчанию нет: до настройки всем доступен только просмотр.

1. Опубликуйте файлы. Существующий GitHub Actions workflow проверяет код и загружает сайт по FTP при push в `main` в `/domains/dandomi.tech/public_html/`.
2. В терминале хостинга выполните:

   ```bash
   cd /domains/dandomi.tech/public_html
   php scripts/configure-admin.php
   ```

   Введите логин и дважды пароль длиной от 12 символов. Скрипт сохраняет только хеш пароля в `/domains/dandomi.tech/windows11x-private/config.php`. Если хостинг использует другой путь, сначала перейдите в фактическую папку сайта.
3. Откройте сайт → **Войти** → **Редактировать**. Содержимое редактора применяется кнопкой **Сохранить на сервере**; отметки и заметки сохраняются автоматически, результат виден в строке состояния.

Если терминала на хостинге нет: запустите `php scripts/configure-admin.php` на компьютере с PHP и загрузите созданную папку `windows11x-private` рядом с `public_html` через файловый менеджер/FTP. Не помещайте её внутрь `public_html`. PHP на хостинге должен иметь право читать конфигурацию и создавать файлы в этой папке (владелец — пользователь PHP; обычно папка `0700`, конфигурация `0600`).

Повторный запуск скрипта меняет пароль и делает прежние сессии недействительными. Время входа — 8 часов. Пароли не передавайте в чат и не коммитьте.

Другие варианты настройки — переменные окружения PHP:

| Переменная | Назначение |
| --- | --- |
| `ATLAS_PRIVATE_DIR` | Абсолютная закрытая папка данных вне корня сайта. По умолчанию `../windows11x-private` относительно корня сайта. |
| `ATLAS_ADMIN_USER` | Логин, по умолчанию `admin`. |
| `ATLAS_ADMIN_PASSWORD_HASH` | Результат PHP `password_hash()`, имеет приоритет над `config.php`. |

При ограничении `open_basedir` разрешите PHP доступ к закрытой папке через настройки хостинга. Пароль и данные не следует переносить в публичный каталог для обхода ограничения. Для крупных архивов рекомендуется `post_max_size=16M` и `memory_limit=128M` или больше; API принимает до 12 МиБ JSON.

## Существующие данные

Исходные 86 документов и первоначальный план остаются стартовым срезом. После первого сохранения серверная версия имеет приоритет над `content-defaults.js` и `research-data.js`. Следующее FTP-обновление её не затирает: изменяемые файлы находятся вне `public_html`.

Старые отметки из браузера **не публикуются автоматически**. Откройте сайт в прежнем браузере, войдите и нажмите **Перенести старый локальный план**, либо используйте старый **Экспорт JSON** → **Импорт**. Локальная копия остаётся нетронутой. При редактировании содержимого свои шаги переходят в обычные редактируемые задачи с сохранением ID, отметок и заметок.

## Резервные копии и конфликты

**Скачать полную копию** выгружает всё содержимое и общий план. Владелец может вернуть её через **Восстановить копию**. Старый экспорт плана также поддерживается и меняет только отметки, заметки и свои шаги.

В закрытой папке сохраняются `atlas.json` и предыдущая версия `atlas.previous.json`. Перед важными изменениями скачивайте полную копию; для долгой истории настройте резервное копирование закрытой папки на хостинге.

Две вкладки не могут незаметно перезаписать друг друга. При конфликте сохранение блокируется: скачайте полную копию своих изменений, нажмите **Загрузить актуальные данные** и повторите нужные правки. При ошибке сети можно повторить сохранение. Не закрывайте вкладку до сообщения **Сохранено на сервере**.

Все данные атласа, включая заметки, публичны по задаче проекта. Пароль защищает изменение. Проверка прав выполняется на сервере для каждой записи, а не только скрывает кнопки. Используются PHP-сессии, CSRF-токен, ограничение попыток входа, проверка структуры данных, атомарная запись и проверка ревизии.

## Файлы и проверки

- `index.html`, `styles.css`, `app.js` — интерфейс и отображение.
- `editor.js` — вход, редактор и синхронизация с сервером.
- `comments.js` — обсуждения задач и перенос прежних заметок.
- `content-defaults.js` — стартовые настройки, тексты и структуры.
- `research-data.js`, `library/` — стартовые документы. Скачивание из читателя отражает текущий, в том числе отредактированный, текст.
- `api/index.php` — чтение, авторизация и запись.
- `scripts/configure-admin.php` — настройка владельца, работает только из CLI.

```bash
node --check app.js
node --check editor.js
node scripts/smoke-ui.js
php -l api/index.php
php -l scripts/configure-admin.php
python3 scripts/test-api.py
```

Проверка API запускает отдельный PHP-сервер со случайным паролем и временной папкой: гостевой доступ, запрет записи без входа, CSRF, вход/выход, сохранение всех 86 источников, чтение другим клиентом, новые этапы/даты/документы, конфликт ревизий, валидация, резервная версия и ограничение попыток входа. Рабочие данные сайта она не затрагивает. При необходимости задайте `PHP_BIN` с путём к PHP CLI.

## Актуальный контекст и MCP для ИИ

На сайте появилась кнопка **Для ИИ**: ссылки на контекст, копирование свежих данных, инструкция для беседы и список разрешённых подключений с отзывом доступа.

| Адрес | Назначение |
| --- | --- |
| `https://dandomi.tech/ai-context.php` | Тексты сайта, план, точные ID задач и критерии галочек, все комментарии, каталог исследований и последние изменения. |
| `https://dandomi.tech/ai-context.php?full=1` | То же и полные тексты всех исследований; может быть слишком большим для одного контекстного окна. |
| `https://dandomi.tech/api/mcp.php` | Удалённый MCP через stateless Streamable HTTP, JSON-ответы, протоколы 2025-03-26 / 2025-06-18 / 2025-11-25. GET SSE не используется (405). |
| `https://dandomi.tech/api/index.php?action=version` | Свежая revision и дата сохранения без загрузки всех документов. |
| `https://dandomi.tech/llms.txt` | Указатель для агентов на актуальные источники. |

Данные берутся из того же серверного файла, что и интерфейс. До первого сохранения PHP читает исходный JSON из `content-defaults.js` и `research-data.js`, не исполняя JavaScript. GitHub хранит код и исходный срез; актуальные записи владельца/ИИ нужно читать с сайта. Каждый ответ содержит revision, время последнего сохранения и/или чтения; контекст не кешируется. Страницы сайта проверяют новую версию каждые 30 секунд и при возврате в окно, загружают её при отсутствии черновиков, а при конфликте предлагают сохранить копию и перечитать данные.

### Подключение к ChatGPT

Откройте **Плагины → + → Добавить пользовательский MCP-сервер**, задайте имя Windows11X, адрес MCP из таблицы и **OAuth**. Если предлагается выбор регистрации, используйте **DCR**. Статические Client ID / Client Secret не требуются: клиент регистрируется автоматически. Установите созданный плагин, подключите его к беседе через **@** и на странице нашего сайта войдите существующим логином владельца, затем разрешите доступ. В других клиентах нужен удалённый MCP с OAuth 2.1 / PKCE S256 и DCR. Если клиент поддерживает смешанную авторизацию, инструменты чтения объявлены `noauth`, инструменты записи — OAuth `atlas:write`.

Точный интерфейс подключения зависит от приложения и доступных в аккаунте возможностей. Инструкция и схемы сверены с официальной документацией: [Custom MCP](https://developers.openai.com/api/docs/guides/custom-mcp-server), [OAuth](https://developers.openai.com/plugins/build/auth), [MCP transports](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

Это не фоновая подписка и не гарантия поведения любой модели. Скопируйте инструкцию кнопкой **Для ИИ → Скопировать инструкцию и ссылки** в инструкции проекта/беседу. Она требует вызывать `get_project_context` перед новыми выводами и советами о галочках, читать нужные источники целиком, указывать revision и честно сообщать об ошибке чтения. У ИИ есть точные taskId, названия, этапы, критерии `proof` и прямые ссылки вида `/?task=g2-dual#plan`; интерфейс также показывает ID возле задачи.

### Инструменты

| Инструмент | Доступ | Результат |
| --- | --- | --- |
| `get_project_context` | Публичный | Весь актуальный контекст, задачи и комментарии, каталог исследований; тексты документов отдельно. |
| `get_task` | Публичный | Точная задача, состояние галочки, критерий, комментарии и ссылка. |
| `get_research` | Публичный | Текст исследования с пагинацией в символах Unicode. При `nextOffset != null` читайте следующую страницу. |
| `search_research` | Публичный | Поиск по полным текстам с отрывками и пагинацией. |
| `get_changes` | Публичный | До 100 последних сохранений с автором и операцией. |
| `add_comment` | OAuth | Датированный результат с источником и уровнем доказательства. |
| `set_task_status` | OAuth | Галочка плюс комментарий с критерием, доказательством и источником. Гипотеза / непроверенный / неудачный опыт не разрешают поставить галочку. |
| `add_task`, `update_task` | OAuth | Новая невыполненная задача или уточнение задачи с сохранением ID, галочки и комментариев. |
| `save_research` | OAuth | Создание или обновление исследования по ID. |
| `save_timeline_entry` | OAuth | Событие или дополнение существующего дня без потери прежнего текста. |

Запись использует `revision` из свежего чтения и общий файловый lock с интерфейсом. При несовпадении возвращается конфликт с текущей версией, без изменения данных. ИИ должен перечитать данные и пересмотреть действие. Успешный ответ содержит новую revision. Последнее сохранение резервируется в `atlas.previous.json`; последние 100 операций хранятся с данными в `changes`. Это ограниченная история операций, а не архив всех версий документов. Полная копия содержимого доступна существующей кнопкой экспорта.

Даты исследования не подменяются временем загрузки. Для комментариев, исследований, хронологии и галочек ИИ обязан указать `researchDate`, `source`, `evidenceLevel`. Сервер проверяет наличие и формат, но не может самостоятельно доказать истинность текста: соответствие критерию остаётся задачей исследователя и ИИ. Исследования/комментарии объявлены недоверенными данными, не командами для агента.

### Настройка сервера и доступ

При текущем домене и уже настроенном владельце дополнительных секретов не требуется. На Apache 2.4 нужна поддержка `.htaccess` / `mod_rewrite`: файл публикуется по FTP и предоставляет discovery по `/.well-known/oauth-authorization-server` и `/.well-known/oauth-protected-resource/api/mcp.php`, а также передаёт Authorization в PHP CGI. Метаданные доступны и напрямую по `/api/oauth.php?action=metadata` и `?action=resource` (последний адрес указан в WWW-Authenticate).

Нужен действительный доверенный SSL-сертификат домена; самоподписанный сертификат не подходит для удалённого MCP/OAuth. Выпустите сертификат, например Let’s Encrypt, и назначьте его сайту в панели хостинга. После FTP workflow проверяет реальные HTTPS-адреса командой `python3 scripts/check-live.py`; ошибка этой проверки после успешного FTP означает, что код загружен, но работа опубликованных адресов ещё не подтверждена. Проверка сертификата не отключается.

При смене домена задайте `ATLAS_BASE_URL=https://ваш-домен` или `'base_url' => 'https://ваш-домен'` в существующем закрытом `config.php`, сохранив логин и хеш пароля. URL должен быть origin без пути. Значение Host-заголовка не используется для генерации OAuth-адресов. Для локальных проверок разрешён HTTP только на localhost/127.0.0.1. На Nginx настройте аналогичные два маршрута discovery.

OAuth использует динамическую регистрацию public client, точный redirect URI, обязательный PKCE S256, одноразовый код на 5 минут, привязку к MCP resource и issuer, access token на час, обновляемый refresh token на 30 дней. В закрытом `oauth.json` сохраняются только хеши токенов; при обновлении предыдущие токены аннулируются. Владелец может отозвать каждое подключение в **Для ИИ**; смена логина или хеша пароля также аннулирует сессии и OAuth. Публичный список инструментов не даёт права записи, сессия браузера сама по себе не авторизует MCP-запрос.

Дополнительная интеграционная проверка: `python3 scripts/test-mcp.py`. Она использует случайные временные пароль/порт/закрытую папку, проходит реальный OAuth-цикл и не затрагивает рабочий сайт.
