# Windows 11X / WCOS 26100 — минимальный контракт портирования `statesepext` Phase0

Дата исследования: 2026-11-08. Статический анализ оригинальных PE, **без изменения PoC01**.

## Исходные компоненты

- Factory OS 22000.1 `statesepext.sys`: SHA-256 `167fda36a71c2aad4c146bc66ae4c83e9d525d008d6abfd8eda0e056c9a96658`.
- Windows NT 26100.1742 `ntoskrnl.exe`: SHA-256 `93db70780a95192d13d04b4c3cb49c22a138063adba5c83d4855be02b645fdd0`.
- Повторно использовать уже предоставленные пользователем `apisetschema.dll` и `winload.efi`; повторный сбор файлов с PoC01 не требуется.

## Почему простое копирование `.sys` не работает

1. PE-файл не запускается от нахождения на диске. Схема API Set определяет связь контракта ядра с модулем-хостом; в 26100 у State Separation контракта отсутствует host и стоит `SEALED`.
2. Подключение через обычную службу-драйвер не эквивалентно kernel extension. `statesepext.sys` имеет специальные экспорты ранних фаз и его обычный entry point не предполагает стандартный успешный DriverEntry.
3. Windows 26100 сохраняет реальные callsite `ExpInitializeStateSeparationPhase0/1/2`, но их импорт в проверенной работающей системе ссылается на резервный обработчик `STATUS_NOT_SUPPORTED`.
4. State Separation требует не только кода модуля, но и соответствующей загрузочной конфигурации, раннего реестра, имен пространств `OSDataRoot` и перенаправлений; полноценная защита MainOS — отдельный слой.

## Точно подтверждённый код Phase0 в оригинале 22000

Экспорт `ExpInitializeStateSeparationPhase0` — RVA `0x8090` в секции `INIT`; следующая экспортированная `Phase1` начинается с RVA `0x8190`.

- При `CL=0` происходит ранний переход к завершающему участку без выполнения основной работы.
- При `CL!=0` и `DL!=0`: строится набор параметров реестра и вызывается `ZwOpenKey` через IAT RVA `0x5000`; при успехе используется `RtlInitUnicodeString` через IAT `0x5008` со строкой `DevModeEverEnabled`, затем `ZwSetValueKey` (`0x5010`) и `ZwClose` (`0x5018`).
- Далее управление переходит к внутреннему helper RVA `0x8644` с аргументом-флагом в `CL` (из `DL`); при неотрицательном статусе запускается ещё один helper RVA `0x9344`.
- Исходная `Phase0` использует возвращаемые статусы внутренних helper и зависит от состояния реестра; её нельзя заменить просто `return STATUS_SUCCESS` без утраты поведения.

### Что нужно установить до написания совместимой реализации

1. Точный тип и значения двух флагов, передаваемых ядром 26100, и что означает «нормальный» путь без State Separation.
2. Полный граф побочных эффектов функций `statesepext!+0x8644` и `+0x9344`, включая NT-имена объектов и доступность реестра в момент вызова.
3. Порядок подготовки `OSDataRoot`, `SYSTEM`/`SOFTWARE` и начальных hive objects до Phase1.
4. Конкретный технически допустимый путь **ранней привязки** совместимого модуля к NT 26100. Нельзя подразумевать, что простое присутствие файла обеспечивает загрузку или привязку.
5. Соответствие ожидаемым требованиям подписи загрузочных компонентов.

## Минимальный критерий первого PoC

На **той же существующей Hyper-V PoC01**, только после 1–5 и на восстанавливаемом VHDX: ядро 26100 вызывает реальную Phase0/Phase1/Phase2 из загруженного совместимого расширения (не заглушки), при активном режиме; система проходит загрузку; изменения проверяемо переживают перезагрузку на OSData. Это всё ещё не полное доказательство MainOS read-only.

## Что не делать сейчас

Не копировать 22000 `statesepext.sys` в гостевую систему и не включать `StateSeparation\\Policy\\Enabled=1`; не добавлять его как стандартный `SERVICE_BOOT_START`; не менять подписанные `ntoskrnl.exe`, `winload.efi` или `apisetschema.dll` в PoC01; не объявлять Registry links или отдельный том работающей State Separation.
