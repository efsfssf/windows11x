# INCOMPATIBLE — установленные несоответствия конкретных сценариев

Эта категория относится к названному состоянию или способу использования. Она **не** означает, что вся архитектура22000 несовместима с NT26100. Где нет прямого отрицательного доказательства, используется UNKNOWN.

## I01 — исходная база26100 не выбирает State Separation Host

Оригинальная ApiSetSchema26100.9278: compact family647 не имеет default-host record (indexFFFF, flags0x10, importer count0); version710 SEALED=1. V7 resolver при этих данных возвращает marker1 и пустой Host. Поэтому исходная mapping не выбирает ни FOS statesepext.sys, ни другой State Separation implementation.

Это **не выполненное условие интеграции** для «настоящей State Separation с данным Host», а не доказательство несовместимости самого Phase ABI. Обычный extension overlay существующего SEALED version ограничивается проверками composer; план обхода здесь не предлагается. Предыдущий аудит установил, что SEALED-контракты с непустым Host в базовой schema вообще существуют, например tm.sys.

Та же проверка исходной user-mode core-stateseparationext mapping даёт отсутствие Host. Даже успешное решение kernel стороны не докажет готовность всего пользовательского слоя.

## I02 — F не является обычным драйвером с успешным DriverEntry

Оригинальный F entry RVA `0x8010` после cookie initialization вызывает F `0x8078`; там bytes `b8 01 00 00 c0 c3`, то есть STATUS_UNSUCCESSFUL. Нельзя считать обычную service/DriverEntry загрузку этого образа эквивалентом kernel-extension binding, где ядро вызывает Phase exports.

Отрицательный результат этого entry — прямое доказательство для указанного сценария. Он не запрещает штатное использование PE через предназначенный ему extension path и не объясняет сам по себе loader trust requirements.

## Чего в эту категорию не включено

- Номер build22000 вместо26100 сам по себе не доказывает breaking ABI change.
- Отсутствие XRo/SSBoot в старом inventory одного retail WIM не доказывает отсутствие всех реализаций26100.
- INIT у Phase2 плюс PAGE у WNF caller — серьёзный lifecycle вопрос, но без правила discard/retention это UNKNOWN, не доказанный crash.
- Отсутствие подтверждённого раннего OSBOOT/OSData backend и servicing-комплекта — незакрытые условия. Из офлайн-копий PE нельзя объявить текущее состояние конкретной VM невозможным или безопасным.
- Сравнение 26 имён не доказывает одинаковую семантику registry/file/security APIs; отсутствие kernel22000 не доказывает различие.

Фундаментального несовпадения машинной архитектуры, внешней Phase сигнатуры или отсутствующего NT export из 26 импортов **не установлено**. Препятствия I01/I02 реальны для описанных конфигураций, но не являются доказательством универсальной невозможности дальнейшего исследования.
