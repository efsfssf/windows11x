# Windows 11X / WCOS — актуальный контекст проекта

**Обновлено:** 2026-11-05. **Назначение:** главный ориентир для следующих чатов и технической работы.

## 1. Неизменная главная цель

Создать **Windows 11X** — реальную, загружаемую на x64 ПК **современную Windows Core OS**, а не обычную Windows 11 с темой оформления, облегченными службами и переименованными разделами. Нужны современные системные компоненты Windows (первая целевая ветка **26100**, в будущем — обновляемость на новые ветки), настоящая **State Separation** и архитектура наподобие Factory OS / Windows 10X.

### Критерии успеха ядра проекта

- Согласованная загрузка системных компонентов Windows NT **26100** (или новой ветки) в Hyper-V Gen2.
- Доказанная защита **MainOS** и перенос изменяемого состояния в **OSData**, включая необходимые части системного реестра.
- Согласованная схема **Storage Spaces**, загрузочных и служебных томов WCOS там, где это необходимо выбранной оригинальной архитектуре; названия томов не считаются доказательством.
- Сохранение нужного состояния после перезагрузки; механизм обновления, обслуживания и восстановления не разрушают систему.
- Минимализм хост-ОС: избегать SysWOW64 и обычного Win32-хоста по возможности, но не ломать основу до проверки совместимости.
- **Позже**, после успешного WCOS Core: UWP/WinUI, простая совместимая оболочка (возможно UWP), оригинальная **Santorini/Composer** из 20279, Win32 через изоляцию/контейнер (пока не доказана осуществимость).

## 2. Выбранная исследовательская стратегия

**Нельзя исходить из предположения, что готовая WCOS 26100 для ПК существует или что её можно собрать подменой DLL.** Исследуем, что из архитектуры Factory OS сохранилось в современных 26100 компонентах. Только после технического подтверждения создаем минимальный boot PoC.

| Источник | Роль | Что НЕ следует предполагать |
|---|---|---|
| **Windows 11 IoT Enterprise LTSC 2024 x64 / Enterprise LTSC 2024 x64 (26100)** | Кандидат в источник современного согласованного набора PC-системных компонентов; IoT предпочитается для первого исследования | Ни обычная Windows 11, ни IoT автоматически не являются WCOS; срок поддержки Microsoft не переносится на модифицированную ОС |
| **Factory OS 22000** | Эталон настоящей PC WCOS: загрузка, State Separation, Storage Spaces, обслуживание, WSK | Нельзя просто заменить ядро 22000 на 26100 |
| **Windows 10X 20279** | Эталон Santorini, AppModel, пользовательской WCOS; OOBE-исследования сохранены | Не современная поддерживаемая база для финального Windows 11X |
| **Validation OS 26100** | Необязательный источник сравнения минимальной Windows | Не готовая WCOS и не основной выбранный фундамент |
| **Xbox SystemOS/GameCore (ветка 26100)** | Ориентир и косвенные архитектурные сведения о современной специализированной Windows | Xbox OS не является переносимой на обычный ПК Factory OS; не подменять доказательства совпадением номера сборки |
| **Windows Holographic (22621)** | Дополнительный пример развития специализированной Windows | Не означает, что существует полноценная PC WCOS 26100 |

**Первый приоритет:** Core 26100 + State Separation. **Отложено:** OOBE, Santorini, Factory Composer, UWP shell, Win32-контейнеры.

## 3. Что известно из документации WCOS

- Для Factory OS документированы функции WSK `STATESEPARATION_ON`, `STORAGESPACES_LAYOUT`, `UEFI_VM`, `SERVICING_STACK` и диагностические режимы запуска. Применимость WSK именно к 26100 **не доказана**.
- Схема Factory OS включает MainOS, OSData, Data, варианты EFI/BSP и отдельные служебные тома; фактическая конфигурация различных редакций отличается.
- **State Separation — не просто разделы.** Включает файловые и реестровые правила и определенную модель обслуживания.
- `RtlIsStateSeparationEnabled` документирован; присутствие функции/строки в DLL или ntoskrnl **не доказывает** способность включить WCOS в обычной Windows.
- Xbox SystemOS 26100 — интересная исследовательская зацепка, но не готовый донор аппаратно-независимой PC WCOS.

## 4. Результаты по Windows 10X 20279 (сохранять, не повторять)

- Рабочая эталонная `10X-20279-clean-test` загружается до OOBE; интернет присутствовал **при всех тестах**, проблема не в отсутствии сети.
- `CloudExperienceHostAPI.UserManagementStatics.provisionNewCoreLocalAccountAsync(true)` **и** `(false)`, а также `provisionNewCoreRDXLocalAccountAsync()` → `0x80070005 Access denied`; локальный пользователь не создан.
- CloudExperienceHost capabilities: `userSigninSupport=4` (Allowed); `userManagementSystem=1` (NotDeclaredByApp); `cloudExperienceHost=4`; `shellExperience=1`. Это наблюдения, не доказанная цепочка причины ошибки.
- `CloudExperienceHostBroker.Account.LocalAccountManager` при создании → `0x80040154 Class not registered`.
- WinRT `Windows.System.Internal.UserManager` зарегистрирован (`Server=UserManager`, `Identity=nt authority\system`, `ServiceName=UserManager`). У службы `ServiceDll=%SystemRoot%\System32\usermgr.dll`, `WindowsCoreUserModelEnforced=1`, `DeviceAccessBrokerConsentRequired=1`, зависимость `RpcSs`, `ProfSvc`.
- Оригинальная `usermgr.dll` из 20279 сохранена и анализировалась; были найдены участки с `0x80070005` и проверкой `userSigninSupport`, но **динамический источник отказа не доказан**.
- `ModernUXShellApp.exe` 20279: пакет `ModernUXProduct 1000.20279.1002.0`, зависимости `Microsoft.UI.Xaml.2.4` и `Microsoft.VCLibs.140.00`, приватные `WindowsInternal.ComposableShell`, capabilities `shellExperienceComposer`, `windowManagementSystem`. PE: 54 обычные DLL-зависимости + 2 delay-import; импорт `RtlIsStateSeparationEnabled`. Совместимость на 26100 **не проверена**.
- Не повторять Sysprep/unattend, пять нажатий Win/.ppkg, cmd внутри основной WCOS, сеть, изменение `isDeviceOwner`, попытки Retail Demo без новых данных.

## 5. VM и безопасная работа

- Эталон Windows 10X: `10X-20279-clean-test` (`C:\ProgramData\Microsoft\Windows\Virtual Hard Disks\10X-20279-clean-test.vhdx`). Не изменять.
- Базовая копия: `E:\WCOS\Backups\10X-20279-offline-exp01-baseline.vhdx`. Не изменять.
- Диагностическая `10X-20279-offline-exp02`: `E:\WCOS\Work\10X-20279-offline-exp02.vhdx`. Secure Boot был отключен для эксперимента; COM1 `\\.\pipe\WCOS20279Exp02Dbg`, но BCD гостя не был изменен и WinDbg не был подключен. Последний раз пользователь подтвердил успешную загрузку после освобождения VHDX.
- VM `FOS` с Factory OS 22000 использует `.avhdx` и checkpoint: не изменять родительский образ при существующей цепочке.
- В одном из тестов монтирования `exp02` получил блокировку VHDX при состоянии `Attached=True` и ошибке `Get-Disk`. Отключение через `Dismount-DiskImage` восстановило возможность запуска. Не монтировать VHDX одновременно с VM; не делать лишних больших копий.

## 6. Следующий рабочий шаг

1. Получить официальный исходный **Windows 11 IoT Enterprise LTSC 2024 x64, 26100** (или Enterprise LTSC 2024) и сохранить исходный ISO/WIM без изменений.
2. Запустить read-only `Collect-WCOS-Core-26100.ps1` на фактической 26100 или извлеченных файлах; предоставить `WCOS-Core-26100-inventory.json`.
3. Инвентаризировать компоненты **Factory OS 22000** в безопасной отдельной копии, не нарушая VHDX/AVHDX цепочки.
4. Сравнить загрузчик/BCD, Storage Spaces boot, State Separation, хранение реестра, image packages, драйверы, servicing и политики; определить реальные несовместимости.
5. Выбрать один минимальный загрузочный эксперимент, задать stop/go-критерии до модификации образов.

**Важно для дальнейших помощников:** не подменять цель сборкой обычной урезанной Windows, Validation OS, UWF/overlay или косметическим подобием WCOS. Если оригинальные механизмы недоступны и понадобится новая собственная реализация, прямо называть её новым state-separated Windows-проектом, а не оригинальной Microsoft WCOS.

## 8. Примечание о достоверности

Подтвержденные пользователем результаты, данные локального анализа и сведения из публичной документации разделены. Наличие соответствующего имени файла, ключа реестра, API или функции **не доказывает совместимость WCOS 26100**. На момент подготовки нет проверенного загружаемого WCOS 26100 и нет фактической сравнительной инвентаризации 26100 vs Factory OS 22000.
