## Доказанная необходимая цепочка

`выбранный loader SYSTEM → BaseApiSetSchema → принятый schema PE → .apiset copy → OslApiSetSchema → OslpLdrExOverrideImport → ApiSetResolveToHost → принятый host PE → BlLdrBindImportReferences → NT Phase0/1/2`.

Это конкретная техническая возможность в коде загрузчика. Для `GO` отсутствуют **два артефакта и одно доказательство**: согласованная schema с целевым kernel host, совместимый фазовый extension, доказанное принятие обоих именно boot policy/signing scenario. Офлайн-структурный валидатор не может честно превратить их отсутствие в `GO`.

## Граница вывода

Нельзя заключить «альтернативная schema принципиально не загружается»: код её выбирает. Нельзя заключить «достаточно собственного test certificate»: код применяет image flags и policy, а результат для этого сертификата/образа не получен. Нельзя заключить «нужен исключительно внутренний Microsoft signer при всех настройках». Однако конкретный новый официальный custom-kernel-signers механизм в текущем коде **не расширяет root set для base schema scenario1**: входит только для scenarios2/3/4/7. Ранний API Set host ядра через context0x110 также попадает вscenario1 (`0x1C180`). Это точное ограничение замены схемы и раннего extension, даже если собственный обычный kernel driver получает допустимую подпись. Следовательно, обоснованное решение — **NO-GO на boot текущего стенда; продуктовый путь через конкретный легитимный совместимый OEM/Microsoft набор, либо независимо доказанный официальный provisioning/signing route для собственного согласованного кандидата**. Последний остаётся открытой инженерной гипотезой, а не предлагаемой процедурой для PoC01.

Следующий практический шаг — передать подготовленный **`OEM-COMPONENT-REQUEST.md`** Microsoft/OEM-поставщику: запросить подлинные согласованные schema и early extension с допустимым **scenario1** trust/provisioning и ранними hive/servicing prerequisites. После получения конкретного комплекта выполнить предусмотренную в `README.md` офлайн-проверку. До выполнения этих предусловий `NEXT-BOOT-EXPERIMENT.md` прямо запрещает boot test.
