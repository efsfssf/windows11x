## Почему арифметика размера содержательна

Исходные поля встроенного представления дают `0x98 + 0x12A14 + 0xC858 + 889×0x14 + 4×0x14 + 984×0x14 + 286×0x14 + 0x60 = 0x29C60` (`0x27BEFC–0x27C012`). Ветка `0x27C5D6` добавляет одну 20-байтную запись при отсутствии соответствующей compact value. Получается `0x29C60+0x14=0x29C74`. Это *кодовое* объяснение возможного конечного размера, совместимое с Trace extension, а не доказательство, что именно эта инструкция выполнилась в VM.

Изменение B legacy value находится по `+0x94F0`, до начала объявленных V7 data blocks `+0xC8F0`; новая строка лежит по `+0x29C60`, непосредственно после их конца. Поэтому V7 композиция способна валидировать B и построить другой namespace без этой строки. Два источника неопределённости: идентичность установленного PE и неизвестные registry extensions до динамической стадии.
